# 人工验收清单

所有条目需要在 Windows/macOS 各自真实 Chrome 上记录 Chrome 版本、操作系统、扩展 commit、时间和结果。未执行写“未验收”，不得用源码检查或 CI 绿色替代。

1. 启动 `node fixtures/server.mjs`，浏览器打开 127.0.0.1:8765，授权此页。
2. snapshot，找到 ORDER-1024 的详情链接；执行 click，读回“订单号：ORDER-1024”。重新列表，滚动订单列表容器并验证滚动位置。
3. fill 备注框为“中文输入验收”，read_text/页面状态验证无旧内容残留。
4. 在另一应用连续选中文字，同时在授权页执行“下一页”并 wait_for“页码：2”；观察系统鼠标、前台窗口和文字选区不被改变。
5. Chrome 缩放 125%，重复详情点击，确认 Lumi 光标与实际命中点一致；把浏览器移到不同缩放比例显示器再重复。
6. snapshot 后刷新列表，再使用旧 ref：应返回 stale_ref；snapshot 后复用节点更改订单，也应拒绝原 ref。
7. 开遮挡层后点击被覆盖元素，应返回遮挡错误，不强制点击穿透。
8. 排队一个等待条件和一个点击，点击前接管；等待与排队点击取消，重新授权前不接受输入。若鼠标按下已发，不可承诺事件撤销。
9. 导航至不同 origin（例如 localhost:8765），原会话失效；仅同源页面也需新的 snapshot refs。
10. 关闭标签、断开调试器、重新加载扩展，授权失效且不自动恢复。重复未知结果的请求不被自动重放。

完整端到端验收必须从本地 Agent 的 MCP 客户端执行上述操作；测试面板只供诊断，不能替代外部 MCP 链路。附加测试：两个 MCP 客户端按同一个 Lumi 控制域串行共享会话（不是身份隔离）；客户端退出不伪装成全局撤销。验证取消请求、Chrome 宿主断线，以及 Browser User 停用或 Core 停止后宿主退出、扩展撤销授权；不存在额外自启动 broker。不能自动重放未知点击。

## 0.3 自动连接回归

- 加载扩展后 ID 应为 `hfhigjgopbjmojflbhhnahpfpnmiaman`，Lumi 主流程无需粘贴 ID。
- 尚未启动 Lumi 时不显示已连接；启动已启用的 Lumi 后自动重试连接。
- 未授权网页时通信可连接，但 list_sessions 不产生有效授权。
- 重启 Core 后旧会话/ref 不可操作、旧点击不重放；重新连接后用户需重新授权。
- 旧端口延迟 ready/断线不得覆盖新端口状态。
- 关闭自动维护时路径失配只提示；开启后仅同 ID 自有注册可自动修复，其他注册拒绝。
- Chrome 真机、休眠/唤醒和重启组合由用户验收，mock/CI 不代替此项。
