# Local IPC boundary

No TCP listener, cloud proxy, GUI, login item or persistent service is used. MCP stdio starts the broker during MCP initialize (or the first tool call); Chrome starts native-host mode when the extension connects. Runtime-only sessions are owned by the first MCP connection that operates them. Other clients may list shared metadata but cannot operate an owned session. Disconnect releases ownership and cancels outstanding operations; this is arbitration among trusted local applications, not authorization against the account owner.

Unix sockets live in an owner-only 0700 home directory and are chmod 0600. IPC peers must present a random runtime-created 0600 token stored there. The token is not a browser authorization and never travels to web content. The installation does not create a token; it is generated only on first use. Windows named pipes also require this token, but Node does not set a custom pipe DACL. Protection against other Windows users therefore depends on the normal private user-profile ACL protecting the token. Shared/misconfigured profiles are unsupported. This does not isolate malicious applications running as the same OS user; Chrome native-host allowlisting and explicit popup authorization remain required.

Startup is serialized by a private directory lock; stale locks expire after 20 seconds. No request is replayed after transport loss or timeout. Failures after broker dispatch are reported as outcome_unknown. Cancellation propagates to the extension, which invalidates the affected session rather than undoing already emitted input.

The broker survives while at least one MCP connection is attached. When the last MCP leaves, it closes all native connections after a one-second race-avoidance grace and exits. A native-only startup has a 30-second grace for an Agent to attach; after that it closes and exits. Native disconnection alone leaves no permanent daemon: without MCP clients the same idle timeout applies. Native disconnection revokes browser authorization; reconnecting never restores it automatically. MCP initialize connects to the broker and keeps it alive; tools/list and ping alone are local. --help exits before any runtime setup.

## Diagnostics

`--doctor --extension-id ID --json` reads existing registration and IPC credentials without creating them or starting a broker. Its dedicated IPC role can only request counts and never holds MCP ownership, invokes browser tools, or extends the broker idle grace. Readiness requires correct native registration, an executable that responds to `--help`, and a live session publication plus active authorization from a native host whose Chrome-supplied argv origin matches the registered extension. An originless manually started native host is not proof of that extension's connection. Origin metadata is attribution within the documented trusted-same-user IPC boundary, not authentication against malicious local processes. Diagnostics disclose counts, not page titles, URLs, or page text.
